# 数据驱动内容

## 概述

所有游戏内容——怪物与关卡——都是纯 JSON，由引擎在加载时校验并编译，
因此新增内容无需改动任何引擎代码。

## 背景

传统做法里游戏内容（怪物类型、关卡编排）是用代码实现的——新怪物
类、新关卡脚本、重新测试整个二进制。内容创作因此成了编程任务，
内容 bug 和引擎 bug 纠缠在一起，非程序员也无法参与。

## 问题

- 加一个怪物要动引擎代码并重新验证整个模拟。
- 关卡设计需要程序员当中间人；id 笔误要到运行时崩溃才暴露，而不
  是在创作时反馈。
- 内容长在绑死浏览器的代码路径里，node 侧测试无法演练「真实的
  游戏」。

## 目标

- 只写 JSON 就能定义新怪物或新关卡。
- 所有交叉引用（怪物 ↔ 精灵 ↔ 移动 ↔ 攻击 ↔ 编队）在数据加载
  瞬间校验，错误双语且点名元凶。
- 同一份数据包原样驱动浏览器游戏与 node 测试。
- 自定义关卡不经服务器、不动仓库即可游玩：下载模板 → 编辑 → 上传。

## 非目标

- 不是通用游戏引擎，也不是可视化关卡编辑器——一个游戏，一套词表。
- 没有可视化编辑器；模板 JSON 的 `_help` 字段就是创作指南。
- 不做热重载/文件监听；内容每次页面加载读取一次（失败可重试）。
- 运行时不加载外部内容包（不从 URL 拉关卡）；上传只能是用户选择的
  本地文件。

## 方案概述

加载时两趟编译（`js/engine.js`）：

- `compileEnemies(raw)` —— 对照 `behaviors.js`（移动/攻击）与
  `sprites.js` 的注册表校验每个怪物，归一化数值与默认值，产出按
  怪物 id 索引的 defs。
- `compileLevel(raw, defs)` —— 校验事件时间线，在编译期展开编队
  偏移（固定种子 → 编排稳定），按 `t` 排序队列，`difficulty` 收敛
  到 [0.5, 3]，记录 `duration`。

一套内容词表取代代码：怪物是（移动原语 × 攻击原语 × 数值调节 ×
精灵 × 掉落表）元组；关卡是 `{t, enemy|boss, count, interval,
formation, y}` 时间线。`js/behaviors.js` 是唯一事实源——编译器的
白名单与运行时的分发读的是同一个注册表，因此新原语的函数一旦存在，
JSON 立刻可以按名使用。

## 详细行为

- **默认值：** 缺 `movement` → `straight`；缺 `attack` → `none`；
  `bulletSpeed` 默认 24；`fireRate` 默认 0（永不开火）。
- **校验错误** 抛出携带 i18n 键与参数的 `DataError`
  （`errEnemyRef`、`errSpriteRef`、`errMovement`、`errAttack`、
  `errCycle`、`errFormation`、`errField`、`errLevelShape`）；界面
  双语渲染并提供重试。
- **cycle 攻击**的子项可内联 `{id, params}` 覆盖参数；`spawn` 攻击
  必须指向已存在的怪物（递归检查）。
- **关卡规则：** 数字 `id`；`events` 按 `t` 排序；`y` 是游戏区高
  度的 0–1 比例；至少一个 `boss` 事件——击杀该敌人才算过关；
  `miniboss: true` + `boss: true` 得到血条与必掉奖励但关卡不结束。
- **上传路径：** 缺 `id` 默认 90；同 id 上传替换旧关；上传只存在
  于当前页面会话。
- **竖屏重映射：** 关卡按 80 行场地编译；运行时使用 144×128 竖屏
  场地时，`createRuntime` 按比例重映射生成行，Boss 垂直居中。

## 用户体验

- 开始界面按钮：**下载关卡模板**（可玩示例，`_help` 数组逐字段说
  明）与 **上传关卡 JSON**（选文件 → 校验 → 编译 → 直接开打）。
- 成功显示友好状态行并立即开局；失败显示点名元凶的双语错误。
- 改仓库数据包的开发者跑 `node test/data-test.js` 得到同样的校验，
  再跑 `node test/engine-test.js` 把每一关完整打通。

## 兼容性与历史影响

无历史行为受影响：这是首次公开发布以来的内容体系。数据形状是增量
的——怪物定义里的未知字段被编译器忽略，关卡文件里的 `_help` 被显式
跳过。

## 数据与隐私影响

内容 JSON 只是游戏数据；不含用户数据，也不被执行（没有
`eval`/`new Function`）。上传的自定义关卡在浏览器本地读取、绝不上传
（见[隐私](../privacy.md)）。本功能未引入新的存储键。

## 性能影响

编译是对约 30 KB JSON 的单趟扫描，实测开销可忽略（整套数据编译远
低于一帧）。编队在编译期展开，游玩期零生成开销。

## 当前局限

- 关卡事件必须按 `t` 排好序（校验器直接拒绝乱序文件，而不是替你排）。
- 每事件 `count` 上限 20、`interval` 上限 5 秒（校验器边界）。
- 事件类型只有怪物生成与 boss 标记（没有关中对白、镜头脚本、环境
  事件）。
- 全新移动/攻击原语仍需引擎侧一个函数——这是设计决定（见非目标）。
